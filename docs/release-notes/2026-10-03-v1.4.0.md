# AnyBuff v1.4.0 — Skills, and a quieter chat

_2026-10-03 · Windows x64 + Android arm64 · renderer and settings changes, no
settings migration, no config change._

## The conversation got quieter

Agent process feedback — thinking cards, tool cards, the streaming placeholder —
had grown until it crowded out the answers it was supposed to support. Each work
segment is now folded behind a single header:

```
▸ Working•••     ← open while the segment runs
▸ Worked         ← folded once its thinking and tools finish
```

- **One status line per work segment.** The header reads `Working` while a tool
  is running, a thought is streaming, or the run is still in flight at the
  timeline tail; it flips to `Worked` when that segment finishes. A group you
  never touch follows the run. Toggling one pins it — expand a finished group to
  keep it open, or fold a running one to get it out of the way.
- **Click to expand, triangle turns down.** Same affordance as the rest of the
  app, keyboard-operable (`Enter` / `Space`) with a visible focus ring.
- **The trailing `•••` is the same CSS three-dot bounce as the stream
  placeholder** — not a glyph — so the two never drift apart.
- **One rhythm for all non-prose blocks.** Thinking cards and tool cards now
  share a single 8px cadence instead of each carrying its own margins.

Smaller things that were loud:

- **Tool summary chips lost their pill.** `Read files · src/config.ts` is now
  just text, with spacing doing the separating.
- **The user message bubble steps back on light themes** — same hue, one step
  lighter, so it stops competing with the reply underneath it.
- **Search jumps land correctly.** A hit inside a folded group expands that
  group first, then scrolls to the row.

Grouping is pure, unit-tested logic (`utils/chat-groups.ts`, 9 tests): body text
closes a group, plain rows — user messages, file-change summaries, compaction
notes, system notices — break it, and the live verdict drives the wording.

## Skills management in Settings

A new **Skills tab** installs, creates, and manages agent skills without
touching the filesystem.

- **Install three ways.** From GitHub — paste `owner/repo` (URLs, `.git`
  suffixes and subpaths all accepted), the repo is scanned for folders holding a
  `SKILL.md`, and a whole skill folder installs in one step. Installs are atomic
  (unique temp dir + rename), so a failed download never leaves a partial skill
  behind. Or import a skill file you already have. Or author one in the app —
  name, description, body — and the `SKILL.md` frontmatter is generated for you.
- **Provenance is stamped.** Every skill is marked `manual`, `file`, or `github`
  with an install timestamp, shown as a badge. Duplicate names are caught at
  install time; overwriting requires explicit confirmation and always replaces
  the whole folder.
- **Global skills.** A toggle lets the model load skills from your home skills
  directory — shared with Claude Code and other harnesses on Desktop,
  app-private on Android.
- **GitHub requests are unauthenticated** (60 per hour). Rate-limit and
  private-repository errors explain themselves inline; public repositories only.

## Tool card icons & message timestamps

- **Each retrieval tool has its own glyph.** The magnifier used to mean both
  "search my code" and "search the web", and fetching a URL wore the same
  paperclip as the composer's attach button.

  | Tool | Icon |
  | --- | --- |
  | `code_search` — search the project | magnifier |
  | `web_search` — search the web | globe *(new)* |
  | `read_url` — fetch a specific URL | chain link *(new)* |
  | `read_docs` — library documentation | stacked layers |

- **Sub-agent spawning matches its sub-agents.** `spawn_agents` now uses the
  same person icon as the `Sub-agent:` cards it creates, instead of a robot. The
  robot icon is gone; the paperclip now means *attachment* only.
- **No stray timestamps after a thinking block.** When a reply went from
  thinking straight into a tool call, the completion time floated between the
  thinking card and the tool card. Timestamps now render only when there is
  something to attribute them to — actual reply text or a plan.

Windows ships as a per-user NSIS installer — no UAC, and the install directory
is selectable. `latest.yml` and the `.blockmap` must be attached to the GitHub
Release alongside the installer, or electron-updater will not see the new build.

Android is signed with the AnyBuff release key (`CN=AnyBuff, …`, cert SHA-256
`f44cf96a…6d820`) — the same certificate v1.3.3 was published with, so this
build installs **over** the existing app with no uninstall step. The bundled
engine runtime (proot rootfs, Node arm64, ripgrep, tree-sitter wasm) ships inside
the APK, so there are no first-boot downloads.
